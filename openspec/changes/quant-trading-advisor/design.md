## Context

当前项目是一个量化交易演示系统。用户需要一个完整的量化交易建议软件，能够输入股票代码、搜索相关信息、进行模型微调，并根据用户输入生成分阶段交易建议以实现期望收益。

系统需要处理：
- 证券数据获取与验证（多源、带时间戳、来源追踪）
- 实时情报层（OCI Generative AI + xAI Grok + X Search）
- 机器学习模型训练、微调与治理
- 交易策略生成与优化（含回测、样本外验证、模拟跟踪）
- 用户配置管理（投资者画像、约束条件）
- 合规门禁与审计留痕
- 角色化工作流（普通用户 vs 研究员）

## 实现基线与真实性状态（2026-08-25）

本设计同时描述“当前可运行基线”和“目标平台架构”。任何页面、接口或平台清单都不得把目标能力、已接线但未配置的能力，或仅浏览器本地保存的交互，标记成已经生产可用。

### 状态定义

| 状态 | 含义 | 页面和接口要求 |
|---|---|---|
| `operational` | 已调用真实服务或真实计算，并具有明确的数据来源、失败语义和必要持久化 | 可以显示“可用”，同时展示来源、时间和作用域 |
| `configuration_required` | 真实适配器已实现，但凭证、配额或外部连接尚未配置 | 显示“待配置”，不得生成替代结果或示例事实 |
| `local_only` | 功能能在单一浏览器或单进程内操作，但没有服务端共享状态、恢复或租户隔离 | 显示“本地草稿/模板预览”，不得显示为机构级可用 |
| `placeholder` | 只有页面、固定返回、空页签或“任务已提交”文案，没有实际执行闭环 | 禁止显示“可用”，入口应禁用或明确标记“规划中” |
| `incomplete` | 核心路径真实可执行，但仍缺少同一模块内的生产级子能力或可靠性闭环 | 可展示已完成子能力，同时逐项列出剩余限制，不得笼统宣称模块全部完成 |
| `simulation_only` | 真实研究或纸面计算，但明确不产生实盘订单 | 必须由服务端策略门强制执行，不能只依赖页面文案 |

## Goals / Non-Goals

**Goals:**
- 提供直观的证券代码输入与验证界面
- 集成多数据源获取证券相关信息（含实时情报）
- 支持多种量化模型的微调、训练与治理
- 生成分阶段、分步骤的条件交易计划
- 支持用户自定义期望收益与风险偏好
- 提供交易建议的历史记录与回测功能
- 实现合规门禁与审计留痕
- 支持角色化工作流（普通用户、研究员、管理员）
- 为每个功能公开真实成熟度、依赖状态、数据来源和持久化范围
- 禁止用静态样例、固定成功响应或浏览器本地状态冒充已完成的服务端能力

**Non-Goals:**
- 不提供实时交易执行功能（仅提供建议）
- 不保证交易收益（市场风险不可控）
- 不支持高频交易策略
- 不提供完整的券商对接功能
- MVP 不连接真实券商执行

## Decisions

### 1. 架构风格：模块化单体 + 异步任务

**选择理由：**
- 避免过早微服务带来的复杂性
- 保留数据源、模型和执行适配器的边界
- 异步任务处理长时间运行的操作（模型训练、回测）
- 待负载或团队规模证明需要时再拆分

**当前基线：**
- FastAPI 模块化单体已运行；情报定时监控拥有应用生命周期内的真实后台循环
- 模型训练仍在请求内同步执行，顶部“后台任务”面板只是客户端请求状态，不是持久化任务系统
- 目标异步架构必须引入任务表、队列、幂等键、取消/重试、心跳和执行历史后才能标记为 `operational`

**备选方案：**
- 微服务架构：过于复杂，MVP阶段不需要
- 纯单体架构：扩展性差，不利于后续拆分

### 2. 前端技术栈：当前产品壳 + React/TypeScript 目标

**当前基线：**
- 实际由 FastAPI 提供 `frontend/public/index.html`、`assets/app.js` 和 `assets/app.css`
- 产品壳与独立登录页按桌面、平板和手机三档响应式布局；窄屏使用抽屉导航、可横向浏览的数据表和不小于 42px 的关键触控区域
- 一级页面使用“决策情报概览、检索实时公开信息、监测项目实时风险”等任务式标题；说明文字只承担范围和边界解释，不再用口号替代功能名
- `frontend/src` 中的 React/TypeScript 代码不是当前 localhost:8000 的运行入口，不能用其组件或测试结果代表当前页面已验证
- 浏览器本地存储目前承载关注列表、候选池、预警、计划、工作区和品牌草稿；机构场景必须迁移到服务端资源

**目标选择理由：**
- React 生态成熟，组件库丰富
- TypeScript 提供类型安全，减少运行时错误
- 适合构建复杂的交互式界面
- 支持无障碍访问（WCAG 2.2 AA）

**备选方案：**
- Vue.js：同样优秀，但 React 在金融领域应用更广
- Angular：过于重量级，学习曲线陡峭

### 3. 后端技术栈：Python + FastAPI

**选择理由：**
- Python 在数据科学和机器学习领域占主导地位
- FastAPI 性能优异，自动生成 API 文档
- 方便集成 pandas、scikit-learn、PyTorch 等库
- 支持异步任务处理

**备选方案：**
- Node.js + Express：JavaScript 全栈，但数据科学生态不如 Python
- Go + Gin：性能更好，但机器学习库支持有限

### 4. 数据存储：PostgreSQL + Redis

**当前基线：**
- 本地运行使用 SQLite `backend/data/quant_advisor.db` 和进程内缓存
- 模型与情报监控已有 SQLite 持久化；浏览器计划/预警与服务端 Webhook/审计仍未进入统一数据库
- PostgreSQL + Redis 是生产目标，不得在本地状态页中显示为已经部署

**目标选择理由：**
- PostgreSQL：支持复杂查询，JSON 字段支持灵活数据结构
- Redis：缓存热点数据，提高查询性能
- 两者结合满足结构化数据和缓存需求

**备选方案：**
- MongoDB：文档数据库，适合非结构化数据，但事务支持不如 PostgreSQL
- MySQL：同样优秀，但 PostgreSQL 在复杂查询方面更强大

### 5. 机器学习框架：scikit-learn + PyTorch

**选择理由：**
- scikit-learn：传统机器学习算法，易于使用和调试
- PyTorch：深度学习框架，灵活性强，社区活跃
- 两者结合覆盖从传统到深度学习的完整需求

**备选方案：**
- TensorFlow：同样强大，但 PyTorch 在研究领域更受欢迎
- XGBoost：梯度提升树，适合结构化数据，但深度学习支持有限

### 6. 数据源：多源聚合策略

**选择理由：**
- 集成多个数据源（Yahoo Finance、Alpha Vantage、Twelve Data、Tushare）
- 提高数据可靠性和覆盖范围
- 支持数据源故障切换
- 所有数据带时间戳和来源追踪

**海外证券当前基线：**
- Twelve Data 通过 `TWELVE_DATA_API_KEY` 与 `TWELVE_DATA_BASE_URL` 在服务端配置，浏览器只读取配置状态与规范化结果
- 版本化 API 提供供应商清单、`symbol_search`、`quote`、`time_series`，返回证券、交易所/MIC、国家、币种、供应商时间、采集时间和时效说明
- 未配置密钥时模块保持 `configuration_required`，查询返回真实 503，不使用 Yahoo 或静态样例冒充 Twelve Data 结果
- Twelve Data 同时加入行情聚合故障切换；只有配置完成时才进入候选数据源
- “实时”不能由平台自行推定，必须服从供应商套餐、交易所授权和返回元数据；生产使用还需完成数据许可与再分发评估

**备选方案：**
- 单一数据源：简单但风险集中
- 自建数据采集：成本高，维护复杂

### 7. 实时情报层：OCI Generative AI + xAI Grok

**选择理由：**
- 使用 OCI Responses API 上的 xAI Grok 4.3 / Grok 4.20 Multi-Agent
- 通过 X Search 获取公开 X 内容，通过兼容 Web Search 获取公共开放网页，并用 Code Interpreter 做去重、计数和趋势计算
- 保留引用、查询窗口、请求工具、实际工具、降级工具和模型版本
- 大模型限制在检索增强、信息摘要和解释层

**工具兼容策略：**
- 首次请求按工作区策略发送 `web_search + x_search + code_interpreter`
- 只有提供商返回明确的 400/422 工具校验错误时，才移除不兼容工具重试；认证、配额、超时和网络错误直接暴露为失败
- `web_search` 被移除时结果状态为 `partial`，并在审计中记录 `requested_tools`、`tools` 与 `degraded_tools`
- 检索结果始终标记为 `best_effort`，不把搜索接口包装成平台全量导出能力

**备选方案：**
- 自建NLP模型：成本高，效果不确定
- 其他大模型API：需要评估成本和效果

### 8. 模型治理：不可变版本 + 环境隔离

**选择理由：**
- 不可变模型版本确保可追溯性
- 环境隔离（研究、训练、正式回测、实时模拟）
- champion/challenger 别名和 shadow 比较
- 建议生成时必须把别名解析并固化为具体版本

**备选方案：**
- 可变版本：简单但难以追溯
- 无环境隔离：风险高，难以保证一致性

### 9. 开放平台边界：租户 → 工作区 → 资源

**选择理由：**
- 个人、机构和客户化交付共享产品内核，但数据归属、角色和策略必须以工作区为边界
- 一个身份可加入多个工作区，并在不同工作区拥有不同角色
- 所有受保护请求需要可信的 `tenant_id`、`workspace_id`、`actor_id`、角色和请求标识
- 客户端工作区切换只负责上下文展示，生产隔离必须由服务端仓储、缓存、任务、对象存储和密钥层强制

**当前实现状态：**
- 已提供平台清单 API、工作区模板、角色清单、品牌主题和连接器目录
- 本地个人空间为活动上下文；机构和客户化空间是信息架构预览
- 数据库行级租户隔离、SSO/SCIM、持久成员关系和租户密钥库尚未实现，因此不得宣称生产多租户就绪

### 10. 扩展模型：清单 + 版本化契约

扩展分为四类：

1. `ProviderAdapter`：行情、基本面、新闻、另类数据和内部数据库。
2. `StrategyPackage`：策略、模型、特征依赖、证据和治理元数据。
3. `WorkspaceAppManifest`：导航、组件、提示词、角色和功能开关。
4. `EventConnector`：签名事件、Webhook、幂等和审计上下文。

扩展不能直接绕过权限、数据授权、模型门禁或审计。安装前必须检查契约版本、权限范围、密钥需求、健康检查和数据许可。

### 11. 客户化方式：配置优先于代码分叉

**选择理由：**
- 品牌名称、标识、主题、导航、连接器和策略包以版本化配置交付
- 核心研究、审计、风险提示和无障碍能力保持统一，减少客户分支漂移
- 仅允许受限设计令牌，不允许通过品牌配置注入任意脚本
- 交付支持共享云、专属私有云和本地化三种配置，必须分别定义数据、密钥、监控和备份责任

### 13. Grok 决策情报：实时地面信号 + 复杂融资推理

**定位：**
- Grok 不是通用聊天入口，而是三个受治理的决策工作流：`realtime-research`、`project-risk` 与 `geopolitical-impact`
- `realtime-research` 按主题、关键词/别名和日期范围分开检索 X 原文与公共开放网页，显示趋势、信息流、引用账本和工具降级状态
- `project-risk` 使用 Grok 实时模型、X Search 和公共 Web Search，聚焦成员国、项目与金融产品的政治、社会、债务、环境和声誉变化
- `geopolitical-impact` 使用 Multi-Agent 推理模型，把中美博弈、印太战略、一带一路竞争和双边关系变化拆解成融资传导链与多情景结果

**统一输入与输出契约：**
- 输入必须包含工作区、对象范围、时间窗口、金融产品、决策问题和监测维度
- 输出必须包含直接结论、结构化维度或传导链、可观察触发条件、假设/未知项、来源账本和 OCI 审计元数据
- 面向用户的摘要、趋势、判断、理由、事件、情景、建议、假设、未知项和来源说明统一使用简体中文；JSON 键、枚举代码、URL、股票代码、模型/工具标识和必要专有名词保持不变
- X 的 `original_text` 作为引用证据按来源原文保留；非中文原文必须在 `content_excerpt` 中附独立中文说明，页面和 PDF 分栏或分段展示，不能用译文覆盖原文
- 中文要求在首次 Grok 请求中完成；返回前仅做非破坏性语言审计并记录英文残留字段数，不覆盖实际分析、不要求重复检索，也不把完整结果再次外发给模型做二次翻译
- 项目风险动作只能是“继续监测、调整条款、暂停复核、条件加速、升级管理层”等人工复核选项，不允许模型直接执行
- 地缘推演至少提供基准、压力、机会三类情景，分别说明项目管道、联合融资、借贷意愿、可行性与风险转移

**证据与降级：**
- X 公开内容默认是未验证观点或声明，必须与官方文件、许可、债务数据和项目内部资料交叉验证
- 无可访问引用的实时事实标记为 `unverified`；不得因为模型语气确定就提高证据等级
- OCI 未配置时接口返回 `configuration_required`，页面只展示分析框架，不生成静态“示例结论”冒充实时结果
- 每次结果记录模型、区域、查询窗口、工具、生成时间、请求标识和工作区；生产环境还需固化提示版本与来源授权策略

**开放平台边界：**
- 三个工作流作为 `IntelligenceWorkflowManifest` 扩展，可按工作区配置模型、来源、提示模板、风险阈值和审批链
- 项目监测清单、情报简报和情景版本必须属于工作区资源，并纳入租户隔离、密钥、配额、审计和保留策略
- 当前本地版本已实现 `realtime-research` 与 `project-risk` 的服务端持久监控、30 分钟至 24 小时固定间隔、应用生命周期调度、立即运行、暂停/恢复、最近结果和执行历史
- 三类工作流的真实或部分成功结果都会保存不可变输入/输出快照；各页面按当前工作区展示分析历史，点击即可恢复当时结果，历史 PDF 直接从快照生成而不会重新查询 Grok
- 本地调度器限定为单应用进程；多实例生产部署必须接入分布式租约、任务队列或集中调度器，防止重复执行
- 去重聚类、材料变化阈值告警、内部项目数据连接器与生产租户隔离仍为后续工作

### 14. 功能真实性门与发布判定

所有模块在页面显示“可用”、进入客户演示清单或被计入版本完成度之前，必须同时满足以下条件：

1. **真实执行：** 请求必须触发真实数据访问或真实计算；固定成功响应、定时器动画和静态样例不能计为功能实现。
2. **持久状态：** 需要跨会话存在的资源必须由服务端保存，并能在应用重启后恢复；`localStorage` 和进程内字典只能标记为 `local_only`。
3. **完整失败语义：** 缺少密钥返回 `configuration_required`，供应商不可用返回明确错误，不能以空结果、示例结果或 HTTP 200 掩盖失败。
4. **来源可追溯：** 外部行情、新闻、X 内容和模型结论必须记录供应商、查询窗口、生成时间、引用和请求标识。
5. **工作区作用域：** 机构资源必须经过身份、角色、工作区和租户校验；仅在前端切换工作区不构成数据隔离。
6. **运行可靠性：** 后台任务必须拥有持久任务编号、状态查询、心跳、超时、取消、重试和幂等控制；多进程部署还需验证不会重复执行。
7. **端到端证据：** 至少通过一次从页面操作到服务端、外部依赖、数据库和结果回显的验收；只测模拟对象或单层接口不能宣称生产可用。

**专项发布门：**

- OCI/Grok 能力只有在目标环境完成带真实 X/Web 引用的验收后，才可由 `configuration_required` 升级为 `operational`。
- “任务已提交”只有在服务端已创建可查询、可恢复的任务记录时才能返回；否则接口必须标记为 `placeholder` 或改为同步执行。
- 预警只有在服务端规则、调度扫描、命中事件和通知投递全部贯通后，才能称为实时监控。
- 模拟组合只有在纸面订单、成交、费用/滑点、持仓估值、收益与风险账本贯通后，才能称为模拟交易闭环。
- `simulation_only` 必须由后端统一执行策略强制；该模式下真实下单和撤单接口应拒绝请求或不挂载，不能仅依赖前端隐藏。
- 健康与就绪接口必须返回各模块的上述状态、依赖和原因，不得用固定布尔值表示整个平台正常。

## Risks / Trade-offs

### 风险1：数据质量与准确性
**风险：** 外部数据源可能存在延迟、错误或不完整
**缓解：** 实施数据验证机制，多源交叉验证，设置数据质量告警

### 风险2：模型过拟合
**风险：** 模型在历史数据上表现良好，但在实际交易中失效
**缓解：** 使用交叉验证，设置过拟合检测机制，定期重新训练

### 风险3：市场风险
**风险：** 交易建议可能导致用户亏损
**缓解：** 明确风险提示，设置止损机制，提供风险评估功能

### 风险4：系统性能
**风险：** 大量数据查询和模型计算可能导致响应延迟
**缓解：** 使用缓存策略，异步处理，性能监控和优化

### 风险5：合规风险
**风险：** 交易建议可能涉及证券投资顾问资质要求
**缓解：** 明确免责声明，仅提供信息参考而非投资建议

### 风险6：大模型幻觉
**风险：** Grok 可能产生不准确或虚构的信息
**缓解：** 限制大模型在检索增强和摘要层，所有事实必须有可访问引用，无引用结果标记为 `unverified`

### 风险7：社交情绪误导
**风险：** 社交媒体信息可能误导投资决策
**缓解：** 社交媒体公开表述与已验证交易披露严格区分，大 V 动态不得单独触发行动建议

### 风险8：能力状态被高估
**风险：** 固定响应、未配置适配器或本地交互被页面显示为“正常”，导致客户把演示能力误认为可交付能力
**缓解：** 已统一采用成熟度状态机，状态接口和页面返回依赖、持久化范围与失败原因；下一步补充最近一次真实外部验收时间

### 风险9：客户端或进程内状态丢失
**风险：** 计划、预警、工作区、审计或 Webhook 在刷新、换浏览器、重启或多实例部署后丢失或分叉
**缓解：** 把共享资源迁移到服务端持久仓储，加入版本、租户键、并发控制、备份和恢复测试

### 风险10：模拟边界失效
**风险：** 平台虽声明仅提供建议，但已挂载的券商下单路由可能被直接调用
**缓解：** 已在服务端增加不可绕过的双开关执行策略门，默认 `simulation_only`，下单与撤单返回 403 并写入审计；隔离回归测试已证明适配器不会被调用
